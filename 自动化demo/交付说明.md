# 客户线索自动分级 · 交付说明

> 一句话：客户从网站/微信/表单进来，系统自动洗干净、查重、打分、分给销售、出日报。
> **不用大模型，不用付费 API，跑一次成本 0 元。**

---

## 1. 这套东西解决什么问题

中小公司最典型的三个漏：

| 漏在哪 | 具体表现 | 钱怎么没的 |
|---|---|---|
| 线索没分级 | 销售按到达顺序跟，先跟到的是垃圾广告 | 高意向客户 2 小时内没人联系，成单率腰斩 |
| 重复线索 | 同一个人从官网、公众号、活动页各提交一次 | 三个销售打给同一个人，客户觉得你们很不专业 |
| 没有日报 | 老板问"这周来了多少线索"没人答得上来 | 投流预算没法复盘，继续往错的地方砸钱 |

这套流程把三件事都自动化：**清洗 → 去重 → 打分 → 分配 → 日报**。

---

## 2. 它到底怎么判断（可解释，不是玄学）

打分是**纯规则**，每一分都能追到原因，客户可以自己改：

| 维度 | 分值 | 说明 |
|---|---|---|
| 强意向词（报价/多少钱/合同/采购/预算/开发票…） | +45 | 只命中一个就加满 |
| 中等意向词（了解一下/咨询/对比/案例/演示…） | +20 | 命不中强意向才看这一档 |
| 预算 | +25 / +15 / +5 | ≥5000 元 / 1000–5000 / 偏低。支持 `1.5万`、`15k`、`¥15,000`、`15000` 四种写法 |
| 目标行业（制造/电商/教育/医疗/法律/房产） | +15 | 命中即加，并把行业写进结果，供分配用 |
| 四项联系方式齐全 | +10 | 姓名+邮箱+电话+正文 |
| 联系方式严重缺失 | −20 | 只有 1 项及以下 |
| 消息过短（<10 字） | −15 | "在吗"这种 |
| 命中垃圾词 | 直接 0 分 | 代开发票/刷单/博彩/贷款/加微信领… |
| 一次性邮箱（mailinator 等） | 直接 0 分 | |

分流线：

- **≥70 分 = hot（高意向）** → 立刻分给销售，状态 `qualified`
- **35–50 分，或 hot 但没写预算** → 标 `needs_review`，人工看一眼
- **35–70 分 = warm** → 进跟进池
- **<35 分 = cold** → 低频培育
- **垃圾词命中 = spam** → 直接归档，不占销售时间

分配规则：**在手的线索最少、且行业对口的销售优先**。行业不对口就不推给他。

## 3. 本机实测结果（真跑出来的，不是编的）

用脚本 `01_一键部署.sh` 从零部署 + 自测，6 条用例全过：

| # | 输入 | 判定 | 分数 | 行业 | 预算 | 归谁 | 需复核 |
|---|---|---|---|---|---|---|---|
| 1 | 8个车间想上AI质检，报价多少？预算10万 | **hot** | 95 | 制造 | 100,000 | 销售A | 否 |
| 2 | 想了解一下诊所案例，有什么功能 | **warm** | 35 | 医疗 | — | 销售B | **是** |
| 3 | 专业代开发票，加微信领免费资料 | **spam** | 0 | — | — | 归档 | 否 |
| 4 | 在吗 | **cold** | 0 | — | — | 销售B | 否 |
| 5 | 同第 1 条原样再发 | **判重，跳过** | — | — | — | — | — |
| 6 | 电商店铺，做合同报价，预算15k | **hot** | 95 | 电商 | 15,000 | 销售A | 否 |

累计口径也验过：跑完 6 条后 `total=5`（第 5 条被判重不计），`hot=2 warm=1 cold=1 spam=1`，`已省 24 分钟`，`成本 0 元`。

第 2 条被标"需复核"是有意设计的：35 分正好在边界上，而且**全文没提预算**。这种线索让机器硬判迟早出事，交给人看一眼最稳。

## 4. 怎么装（客户视角）

前置：装好 Docker（Mac / Windows 都有图形化安装包）。

```bash
bash 01_一键部署.sh
```

脚本自己做五件事：清理旧容器 → 起 n8n → 导入工作流 → 发布并重启 → 跑 6 条自测打印结果。

跑完会给你一个地址：

```
http://localhost:5678/webhook/lead-v2
```

**这个地址就是接线口。** 网站表单、飞书多维表格自动化、企业微信机器人、Zapier，只要能 POST JSON 的都能接：

```json
{
  "name": "张经理",
  "email": "zhang@factory.com",
  "phone": "13800138000",
  "message": "8个车间想上AI质检，报价多少？预算10万",
  "budget": "10万",
  "source": "form"
}
```

只有 `message` 是必须的，其他能给就给——给得越全，分越准。

## 5. 部署时踩过的坑（这是这套东西真正的价值）

n8n 这玩意儿文档写得挺好，但真跑起来一堆暗礁。下面每一条都是**实际卡住过、反复试出来的**，客户自己搞大概率会踩：

1. **`import:workflow` 每次都生成新 ID**，旧副本不会删。`delete:workflow` 在 2.44.6 根本没有这个命令。结果就是：改了代码、导入了新版本，但 webhook 还挂在旧副本上，怎么测都是老行为。必须 `docker rm -f` + 删数据卷，从干净库重来。
2. **`publish:workflow` 之后必须重启 n8n。** 不重启，改动只写在库里不生效，而且命令行会打印一句很容易被忽略的提示。
3. **Code 节点沙箱禁用内置模块。** 想用哈希？`require` 直接被拦。只能手写 FNV-1a。
4. **更坑的是：连注释里出现被禁模块的名字都会被拦。** 报错信息只说"模块被禁用"，完全不会告诉你是注释里那两个字触发的。我排查了两轮才发现。
5. **`$input.all()` 在 webhook 单条触发时只有 1 条。** 所以任何跨请求的"去重""累计"都不能放在函数内的变量里——函数每次都是新执行，变量永远从空开始。必须用 `$getWorkflowStaticData('global')`，或者落库。
6. **这是最难查的一个：Code 节点返回对象的顶层字段，n8n 会再当表达式求值一次。** 我的判断字段莫名其妙变成了整个执行上下文对象，`is_duplicate` 永远读出来是 truthy，所有线索都被判重复。表现是"新鲜的线索说是重复"，但去重代码本身没错。
   - 解法：**不要在顶层放字段，把业务字段全部塞进一个 `payload` 子对象**，下游只读 `payload.xxx`。
7. **IF 节点的布尔条件序列化后容易丢 `singleValue: true`**，导致判断恒真。干脆改成自己算一个 `route` 字符串，用 Switch 节点按字符串分流，不再依赖 IF 的隐式语义。
8. **拷数据库只看 `database.sqlite` 会看到 0 条工作流**——数据在 `-wal` 里。必须把 `-wal`、`-shm` 一起拷。

## 6. 交付清单

| 文件 | 作用 |
|---|---|
| `01_一键部署.sh` | 部署 + 自测一条龙，客户自己就能跑 |
| `lead-scoring.json` | n8n 工作流定义，可直接导入，也可在界面里可视化改 |
| `score_leads.py` | 同一套规则的 Python 内核，不依赖 n8n |
| `对拍.js` | **双引擎对拍**：验证 Python 和 n8n 结果完全一致 |
| `压力测试.py` | 300 条模拟真实表单的压力测试，查误杀/漏判 |
| `交付说明.md` | 本文档 |
| `给客户的一句话.md` | 话术，用来开口 |

配套还有一份 **Python 版规则内核**（`score_leads.py`），不依赖 n8n，自带 18 条断言自测全过。作用是：客户以后想换工具（Zapier / Make / 自研），把这份逻辑搬过去就行，不会被 n8n 锁死。这一条对技术型客户很有说服力。

### 改完规则怎么验证没改坏

规则类系统的最大风险不是"不够聪明"，是**改一处、崩一片**，而且崩了不容易发现。所以交付包里放了两个自检：

```bash
# ① Python 内核自测（18 条断言，含预算解析、字段别名、复核比例）
python3 score_leads.py --selftest

# ② 双引擎对拍（17 条线索，Python 和 n8n 逐条比对分级）
node 对拍.js

# ③ 300 条压力测试（模拟真实表单分布，查误杀/漏判）
python3 压力测试.py
```

`对拍.js` 会打印一张对照表，末尾是 `分级一致 17/17`。**只要有一条 ✗，就说明两边规则跑偏了** —— 典型情况是客户在 n8n 界面里改了词表，忘了同步 Python，或者反过来。上线前跑一遍，全绿再发布。

两个脚本都不需要装额外依赖（`对拍.js` 只需要 node 和 python3）。

## 7. 边界（先说清楚，免得后面扯皮）

- 这套是**规则引擎**，不是大模型。好处是零成本、可解释、结果稳定、能审计；坏处是**认不出没写进词表的新说法**。词表可以改，改完立即生效。
- 默认跑在**一台机器**上，webhook 只监听本机。要对外网开放需要配反向代理 + HTTPS + 鉴权。这部分另算。
- 去重用的是 **7 天滑动窗口 + 指纹**（邮箱或电话 + 正文归一化）。换个人换个邮箱再发同样的话，认不出来。要做企业级去重得上数据库。
- 报表是**累计计数**，不是按天分桶。要按天/按周出趋势图，需要接数据库。
